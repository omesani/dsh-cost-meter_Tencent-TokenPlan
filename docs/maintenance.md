# 维护说明

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `files/lib/tencent-token-plan.js` | 读取配置、解析密钥、TC3 签名、查询及积分转换 |
| `patches/patches.mjs` | 与 cost-meter 的集成位置，不包含密钥与业务查询 |
| `lib/deployment.mjs` | 目录解析、补丁计划、语法检查、备份及事务写入 |
| `install.mjs` / `uninstall.mjs` | 安装与单次回退的命令入口 |
| `check.mjs` | 只读部署诊断及可选真实查询 |
| `verify.mjs` | 已安装目标的模拟响应集成自检 |
| `test/deployment.test.mjs` | 部署边界与真实发布包回归 |

不需要安装额外运行依赖。查询模块复用目标 cost-meter 的网络工具与 DSH 凭据接口。

## 适配新版本

先运行 `node install.mjs --dry-run`。版本号不在实测列表时会提示，但**是否可安装以实际结构与语法预检为准**，无需 `--force`。

如果失败：

1. 在 `patches/patches.mjs` 找到报错的补丁 ID。
2. 对照新发布包的目标文件，确认对应语义是否仍存在。
3. 优先选短而唯一的语义锚点，不包含邻接注释或无关压缩变量。
4. 压缩变量不可避免时，使用有边界和回溯引用的正则捕获；每项必须同时提供 `installed` 检测。
5. 安装、重复安装、回退、自检都通过后，再把实测版本加入 `TESTED_PLUGIN_VERSIONS`。

补丁分组：

- `custom-balance/*`：注册腾讯适配器与凭据变量。
- `store/*`：保存配置时保留适配器，固定端点允许空 URL。
- `typert/*`：RPC 配置枚举。
- `worker/*`：后台保存配置时保留适配器。
- `client/*`：设置页预设、表单及积分文案。

`installed` / 旧补丁兼容检测必须验证完整语义，不能只靠出现字符串 `tencent-tokenplan` 就认定整项已安装。

## 验证

不访问网络的基础测试：

```bash
npm test
```

使用**未打补丁的正式发布包**做回归。将下载包解压到工作目录，传入包含 `package.json` 的目录；测试会复制到临时目录，不改原发布包：

```bash
TOKENPLAN_TEST_PLUGINS="/path/to/1.9.58/package,/path/to/1.9.60/package" npm test
```

这会检查安装、重复执行、锚点不兼容时零写入、安装后手工修改保护、跨版本回退拒绝，以及文件逐字恢复。基础测试本身不代表某个 cost-meter 版本已兼容。

在一次性插件副本安装后，再运行 `node verify.mjs --plugin <副本目录>` 检查积分、签名、env 读取和配置保存。直接导入目标模块需要对应 DSH 依赖可解析，应在已安装的 DSH 环境或具有同等依赖的测试目录运行。

最后用真实账号运行 `node check.mjs --live`，重启宿主并在网页验收。不要将网络自检成功写成“网页已生效”。

## 写入边界

- 所有补丁先在内存构建，任一锚点或语法不符则停止。
- 写入前备份，逐文件原子替换，并校验原内容是否仍一致。
- 途中失败只回退本次已写入的文件；遇到并行修改会保留对方内容并报告。
- 多文件修改不是系统级原子事务；断电或强杀可能中断。保留命令输出的备份目录，必要时重新安装官方插件后重试。
- 不在运行中的 DSH 外部直接改账本，不把自动重启、模型配置迁移或其他服务接进安装器。
- 不根据注释判断账号权限，不在文档中放入实际账号、密钥或曾经失效的权限断言。

## 旧版本迁移

1.x 安装器生成的备份可能没有哈希记录，或只备份了本次小更新。新版回退命令拒绝自动套用这类备份，以免跨版本覆盖。

已有补丁通常可直接运行新版安装器。遇到旧补丁形态无法识别时，先重新安装当前版本的官方 dsh-cost-meter，再运行本补丁；env 文件保留，不要复制旧版压缩文件到新版插件中。
